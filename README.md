# کارگردان 🧭

**سیستم‌عامل زندگی شخصی** — نه کار بیشتر؛ تسلط بیشتر.

> این سیستم قرار نیست زندگی را بدون استرس کند؛ قرار است نگذارد استرس، مدیر زندگی تو باشد.

## فلسفه

مغز محل نگهداری فهرست کارها نیست. کارگردان سه لایه‌ی اول این فلسفه را پیاده می‌کند:

| لایه | چیست | در اپ |
|---|---|---|
| **۱. تخلیه‌ی کامل** | هر چیزی که ذهن را اشغال کرده بیرون بیاید | 🧠 صندوق ذهن |
| **۲. تفکیک مهم از فوری** | چهار وضعیت: **الان / بعداً / منتظر / پارک‌شده** | 📋 برد کارها |
| **۳. سقف جبهه‌های فعال** | مثلاً بیش از ۳ پروژه‌ی فعال هم‌زمان نداری — «۳ جبهه + یک صف انتظار» | 🚀 پروژه‌ها |

وضعیت «پارک‌شده» مهم است: چیزی که آدم را خسته می‌کند فقط کارهای زیاد نیست؛ **تصمیم‌های باز** است.

داشبورد همیشه پاسخ چهار سؤال را می‌دهد: الان کجا هستم؟ چه چیزی واقعاً مهم است؟ قدم بعدی چیست؟ و چه چیزهایی را **فعلاً لازم نیست** حل کنم؟

## اجرای محلی

```bash
npm install
npm run dev
```

سپس `http://localhost:3000` را باز کن.

## استقرار روی Vercel (رایگان)

1. این ریپو را در حساب گیت‌هاب خودت داشته باشی (fork یا push).
2. به [vercel.com/new](https://vercel.com/new) برو و با گیت‌هاب وارد شو.
3. ریپوی **Kargardan** را Import کن.
4. در بخش **Environment Variables** رشتهٔ اتصال دیتابیس را وارد کن (برای هر سه محیط
   Production، Preview و Development):

   | نام | مقدار |
   |---|---|
   | `PRISMA_DATABASE_URL` | `postgresql://USER:PASSWORD@HOST:5432/DBNAME?sslmode=require` |

   هر کدام از `PRISMA_DATABASE_URL` · `POSTGRES_URL` · `DATABASE_URL` · `POSTGRES_PRISMA_URL`
   · `POSTGRES_URL_NON_POOLING` کار می‌کند (به همین ترتیب اولویت بررسی می‌شوند).
5. **Deploy** را بزن. تمام — آدرس `something.vercel.app` مال توست.

> ✅ **هیچ متغیر محیطی دیگری لازم نیست.** کلید ایجنت همکار خودش ساخته می‌شود و
> کنترلش از داخل برنامه انجام می‌گیرد.

بعد از Deploy، در بخش **تنظیمات → وضعیت دیتابیس** می‌توانی ببینی اتصال برقرار شده یا نه.

> 💡 اگر متغیرها را نگذاری هم برنامه کار می‌کند؛ فقط آن بخش زرد می‌ماند و داده‌ها در مرورگر
> ذخیره می‌شوند. برنامه هیچ‌وقت به‌خاطر دیتابیس از کار نمی‌افتد.

## داده‌ها کجا ذخیره می‌شوند؟

در **دیتابیس خودت** (PostgreSQL). به‌همراه یک نسخهٔ پشتیبان در مرورگر:

- ☁️ **منبع اصلی:** دیتابیس Postgres خودت. همه‌چیز آنجا ذخیره می‌شود.
- 💾 **پشتیبان محلی:** `localStorage` مرورگر همیشه همگام می‌ماند. اگر دیتابیس قطع شود،
  برنامه بدون هیچ خطایی با همان نسخهٔ محلی کار می‌کند.
- 🛡 **ضدِ گم‌شدن داده:** نوشتن‌ها «شرطی» هستند — اگر دیتابیس هم‌زمان عوض شده باشد،
  نوشتن رد می‌شود تا داده‌ی تازه از بین نرود.
- 📦 پشتیبان‌گیری و بازیابی JSON هم از بخش «تنظیمات» هنوز در دسترس است.

### 🗑 هیچ چیزی پاک نمی‌شود
هر حذفی فقط یعنی رفتن به **سطل بازیافت** (تب «🗑 سطل بازیافت»). هر موردی با یک کلیک
برمی‌گردد. تنها جایی که داده واقعاً می‌رود، دکمهٔ «پاک‌کردن قطعی» است که فقط خودت می‌زنی.

### چطور داده‌های فعلی مرورگرم را به دیتابیس ببرم؟
اگر دیتابیس خالی باشد و در مرورگر داده داشته باشی، برنامه خودش یک نوار پیشنهاد نشان
می‌دهد: «انتقال به دیتابیس». **هیچ‌وقت خودکار انجام نمی‌شود** و نسخهٔ مرورگر هم پاک نمی‌شود.

## 🤝 ایجنت همکار

کارگردان دو ایجنت دارد:

| ایجنت | دسترسی | کارش |
|---|---|---|
| **ایجنت همکار** | فقط API — بدون دسترسی به سورس‌کد | داده را می‌خواند و **پیشنهاد** می‌دهد |
| **ایجنت مادر** | سورس‌کد + دیتابیس | برنامه را می‌سازد |

### 🔌 کنترل کامل از داخل برنامه — بدون هیچ متغیر محیطی

به تب **«🔌 ایجنت همکار»** برو:

| کار | چطور |
|---|---|
| 🔑 ساخت کلید | خودکار — به‌محض بازکردن تب ساخته می‌شود |
| 📋 دیدن و کپی کلید | با دکمه‌های «نشانم بده» و «کپی کلید» |
| ⏸ **قطع دسترسی** | با یک دکمه — از آن لحظه **حتی با کلید درست** هیچ درخواستی پذیرفته نمی‌شود |
| ▶️ بازکردن دوباره | همان دکمه |
| 🔄 عوض‌کردن کلید | «ساخت کلید جدید» — کلید قبلی فوری بی‌اعتبار می‌شود |

🔴 **کلید توقف فوری است** — نیازی به Deploy دوباره یا راه‌اندازی مجدد نیست. اگر کلیدت
لو رفت، با یک کلیک در را ببند.

🔒 **پیشنهاد = پیشنهاد.** هیچ‌چیز خودکار اجرا نمی‌شود؛ تو در تب «🤝 پیشنهادات ایجنت»
تأیید یا رد می‌کنی، و حتی بعد از تأیید هم می‌توانی برگردانی.

📄 مستندات کامل برای دادن به ایجنت همکارت: `API-ایجنت-همکار.md`
