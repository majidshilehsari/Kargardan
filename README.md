# کارگردان 🧭

**سیستم‌عامل زندگی شخصی** — نه کار بیشتر؛ تسلط بیشتر.

> این سیستم قرار نیست زندگی را بدون استرس کند؛ قرار است نگذارد استرس، مدیر زندگی تو باشد.

## فلسفه

مغز محل نگهداری فهرست کارها نیست. کارگردان سه لایه‌ی اول این فلسفه را پیاده می‌کند:

| لایه | چیست | در اپ |
|---|---|---|
| **۱. تخلیه‌ی کامل** | هر چیزی که ذهن را اشغال کرده بیرون بیاید | 🧠 صندوق ذهن |
| **۲. تفکیک مهم از فوری** | چهار وضعیت: **الان / بعداً / منتظر / پارک‌شده** | 📋 برد کارها |
| **۳. سقف جبهه‌های فعال** | مثلاً بیش از ۳ پروژه‌ی فعال هم‌زمان نداری — «۳ جبهه + یک صف انتظار» | 🚀 پروژه‌ها |

وضعیت «پارک‌شده» مهم است: چیزی که آدم را خسته می‌کند فقط کارهای زیاد نیست؛ **تصمیم‌های باز** است.

داشبورد همیشه پاسخ چهار سؤال را می‌دهد: الان کجا هستم؟ چه چیزی واقعاً مهم است؟ قدم بعدی چیست؟ و چه چیزهایی را **فعلاً لازم نیست** حل کنم؟

## اجرای محلی

```bash
npm install
npm run dev
```

سپس `http://localhost:3000` را باز کن.

## استقرار روی Vercel (رایگان)

1. این ریپو را در حساب گیت‌هاب خودت داشته باشی (fork یا push).
2. به [vercel.com/new](https://vercel.com/new) برو و با گیت‌هاب وارد شو.
3. ریپوی **Kargardan** را Import کن.
4. در بخش **Environment Variables** رشتهٔ اتصال دیتابیس را وارد کن (برای هر سه محیط
   Production، Preview و Development):

   | نام | مقدار |
   |---|---|
   | `PRISMA_DATABASE_URL` | `postgresql://USER:PASSWORD@HOST:5432/DBNAME?sslmode=require` |

   هر کدام از `PRISMA_DATABASE_URL` · `POSTGRES_URL` · `DATABASE_URL` · `POSTGRES_PRISMA_URL`
   · `POSTGRES_URL_NON_POOLING` کار می‌کند (به همین ترتیب اولویت بررسی می‌شوند).
5. **Deploy** را بزن. تمام — آدرس `something.vercel.app` مال توست.

بعد از Deploy، در بخش **تنظیمات → وضعیت دیتابیس** می‌توانی ببینی اتصال برقرار شده یا نه.

> 💡 اگر متغیرها را نگذاری هم برنامه کار می‌کند؛ فقط آن بخش زرد می‌ماند و داده‌ها در مرورگر
> ذخیره می‌شوند. برنامه هیچ‌وقت به‌خاطر دیتابیس از کار نمی‌افتد.

## داده‌ها کجا ذخیره می‌شوند؟

**فعلاً** کاملاً در **مرورگر خودت** (localStorage) ذخیره می‌شوند:

- 🔒 داده‌ها هرگز از دستگاهت خارج نمی‌شوند.
- 📦 پشتیبان‌گیری و بازیابی JSON از بخش «تنظیمات».
- ⚠️ پاک‌کردن داده‌های مرورگر (clear site data) داده‌ها را حذف می‌کند — گاهی پشتیبان بگیر.

**دیتابیس چطور؟** اتصال به Postgres آماده است و وضعیتش را در «تنظیمات → وضعیت دیتابیس»
می‌بینی، ولی **هنوز هیچ داده‌ای در دیتابیس نوشته نمی‌شود**. جدول‌های کارگردان ساخته نشده‌اند
و انتقال داده‌ها مرحلهٔ بعدی است. این کار عمدی است: نوشتن در دیتابیس فقط با تأیید صریح
انجام می‌شود تا داده‌هایت در هیچ مرحله‌ای در خطر نباشد.
